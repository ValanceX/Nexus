# NEXUS v0.3.0 release notes

*Released 2026-09-26.*

v0.3 closes the application lifecycle and makes the runtime opaque. A started application now ends in exactly two ways, with a truthful and monotonic status, and it ends everything it owns: its resources, its application-owned `State`, and every observation stream over them, including `Event.subscribe`. Nothing reachable from a public value can end the application behind its lifecycle's back, or look services up outside the declared requirements. Every primitive's documented contract now matches its implementation.

This is an intentional breaking release within v0.x. See "Upgrading from v0.2".

## Highlights

- **Application-owned `State`: `Application.createState(running, schema, initial)`.**
  - It lives in the application runtime's own scope, and the caller supplies no `Scope`.
  - Its `changes`, every selector derived from it, and `Mesh` `renders` over them end normally when the application stops.
  - Its only typed error is `StateInitError`. Requested once termination has been requested, it creates no `State` and ends as a defect.
- **Lifecycle integrity (N2).**
  - A started application terminates in exactly two ways: `Application.shutdown(running)`, or closing the caller's `Scope` that `start` ran in. Both reach `Stopped` once, release everything, and end every observation stream normally.
  - The status never moves backwards, and nothing changes it after `Stopped`.
  - `shutdown` is idempotent and safe to call concurrently. Every call returns once the status is `Stopped`.
  - **New work is admitted only while `Running` and before any termination request.** From the request on, `createState`, `Runtime.run` and `Runtime.runFork` through the application's runtime are refused, as defects, and the refused effect never starts. Termination first waits for work already admitted (for example, a `createState` in progress) to finish. Admission never waits, so an admitted effect that requests more work can't deadlock.
  - **A resource release that dies doesn't stop termination.** The status still reaches `Stopped`, and every other `shutdown` call, and closing the start scope, completes normally. The one call that performed the termination re-raises the release's original failure, as a defect.
- **An opaque `NexusRuntime` (N3).** The handle is only something to pass to `Runtime.run` and `Runtime.runFork`. No Effect `Runtime`, service `Context` or runtime `Scope` is reachable from it, by type or at runtime.
- **Shutdown completes every observation stream (N1), in a defined order (D4).** Termination closes the application's event bus before it releases any resource. Every `Event.subscribe` stream then ends normally. No event, not even one already buffered, is delivered once resource release has begun.
- **Contracts reconciled with the code (N4).** Every primitive doc's data model, API and errors were checked field by field against the built declarations. The stale claims are corrected, and the dead or unsafe API is removed (below).
- **`Event.publish` is type-directed.** It performs no runtime validation, and its error channel stays `never`. `EventDef.schema` describes the payload, for validation at a real boundary (persistence, synchronization, untyped sources).

## Try it

v0.3 isn't published to npm. From a clone:

```console
$ pnpm install
$ pnpm test        # 14 files, 100 tests
$ pnpm build
```

`tests/lifecycle.test.ts` exercises both termination routes, concurrent and repeated shutdown, admission and refusal, application-owned `State`, and a release that dies during termination.

## Upgrading from v0.2

| Removed or changed | Replacement |
|---|---|
| `NexusRuntime.scope` and `NexusRuntime.runtime` | None: the handle is opaque. Run work with `Runtime.run` and `Runtime.runFork`, with the declared `R`. |
| Public `Runtime.shutdown` | For an application, `Application.shutdown(running)`. For a standalone runtime from `Runtime.make`, close the `Scope` it was made in. |
| The `RunningApplication.shutdown` field | `Application.shutdown(running)`. |
| `Scope.extend(State.create(…), running.runtime.scope)` | `Application.createState(running, schema, initial)`. |
| `ApplicationInitError`'s `EnvironmentResolutionFailed` (never produced) | None. The union is `ServiceGraphFailed`. |
| Running work through a handle after termination (it used to execute) | None. It's refused, as a defect. |
| `Application.shutdown` "never fails" | Unchanged when every release succeeds. When a release dies, the call that performed the termination re-raises that defect after the status is `Stopped`; every other call completes normally. |

Behaviour that changed without an API change:
- `Event.subscribe` streams now end when the application stops.
- A second `shutdown` no longer rewrites the status, and closing the start scope now goes through `Stopping` to `Stopped`.

## Known limitations

- **Non-Effect callers can't see typed errors (O8).** `Runtime.run`'s Promise rejects with Effect's failure wrapper. A caller that needs the typed error runs `Effect.exit` inside `run`.
- **MESH host composition isn't owned by anything yet (O9).** Keeping the on-screen render, relaying renderer events and re-rendering on commit remain the host's job.
- **Capability probing and discovery aren't built (O10).** Resolutions are supplied by the `ApplicationDefinition`.
- **Effects already running when termination begins aren't interrupted by it**, apart from the observation streams that N1 ends.
- **The package's `exports` and packaging layout are unchanged**, and not yet decided.
