# NEXUS v0.6.0 release notes

*Released 2026-09-27.*

v0.6 establishes the **runtime/platform boundary**: what NEXUS is, and what the execution environment supplies. An application's environment now reaches it in exactly one place, the platform passed to `Application.start`. NEXUS no longer names any execution environment. It is a deliberate breaking release within v0.x, like v0.3: three public items that put environment knowledge in NEXUS are removed, with no compatibility wrappers. Every lifecycle, State, Selector, Command, Event, Service, Resource, Runtime, Semantic and MESH adapter contract is unchanged.

Design: [`superpowers/specs/2026-09-27-nexus-v0.6-outline.md`](../superpowers/specs/2026-09-27-nexus-v0.6-outline.md). Evidence: [`architecture/2026-09-27-runtime-platform-audit.md`](../architecture/2026-09-27-runtime-platform-audit.md).

## Highlights

- **One supply point.** `Application.start(app, options?)`, with `Application.StartOptions = { readonly platform?: Application.Platform }` and `Application.Platform = Layer.Layer<Capability.EnvironmentShape, unknown, never>`. The platform is the only way an environment reaches an application. With no platform, the environment is empty: every capability is `Unavailable`, exactly as in v0.5 with no `environment`. `StartOptions` fixes the shape of the start boundary. It is not a configuration bag, and holds only `platform`.
- **Platform resources live and die with the application.** The platform Layer is provided to the application-owned runtime scope. Acquisition runs platform, then application; release runs application, then platform. This holds on both shutdown routes, when the platform fails to acquire, when the application layer fails after the platform acquired, and when a release throws during shutdown. A failed start leaves nothing acquired and returns no handle.
- **Host-owned or application-scoped, invisibly.** A platform supplies implementations as host-owned values (`Capability.EnvironmentLive`) or as resources its layer acquires. Application code sees the same `CapabilityResolution` either way.
- **NEXUS names no execution environment.** `CapabilitySource` (`"native" | "browser" | "remote" | "fallback"`) is gone. A substitute implementation a platform supplies is simply `Available`.
- **A capability is its `id`.** `Capability.tag`, which nothing had ever read, is gone. A type-only phantom member keeps `Shape` inference for `resolve` and `require`.
- **Effect's default services stay Effect's.** NEXUS names none of `Clock`, `Console`, `Random`, `ConfigProvider` or `Tracer`. A platform is the intended place to set them. Precedence is Effect's: the caller of `start`, then the platform, then the application's `runtime` layer. Tests pin this order.
- **Host independence is enforced.** The build compiles `src/` with no ambient types (no Node, no DOM), and architecture tests allow `src/` to import only `effect`, and `@valancex/mesh-runtime` in the MESH adapter.
- **A reference test platform.** `tests/platform/reference.ts`, test-only and not a package, runs the vertical slice and the MESH slice through the new supply point.

## Compatibility and migration

Three breaks, all in the environment boundary:

1. **`ApplicationDefinition.environment` is removed.** Pass the platform to `start` instead:
   ```ts
   // v0.5
   Application.start(Application.define({ name, runtime, environment: resolutions }))
   // v0.6
   Application.start(Application.define({ name, runtime }), { platform: Capability.EnvironmentLive(resolutions) })
   ```
   Runtime behavior is identical: the same map, built at the same point, before the service graph.
2. **`CapabilitySource` is removed, and `Available.source` is dropped.** Delete `source` from resolutions. Code that branched on `source` should branch on `_tag`, or the platform should supply a different implementation.
3. **`Capability.tag` is removed.** Nothing in NEXUS read it. Code that provided `capability.tag` directly never affected `resolve`; supply the implementation through the platform instead.

`Application.start(app)` with no options behaves exactly as v0.5's `start` with no `environment`.

### Existing tests

Five amendments, in three files, touch 6 of the 287 v0.5 test cases; 281 are unmodified. Each amendment only drops `source`, or moves the environment to `start`'s `platform` option. No assertion is loosened.

- `tests/capability.test.ts`, three tests:
  - "resolves to Available…": `source` dropped, and its `source` assertion replaced by a stricter exact-keys assertion.
  - "reports a registered fallback source as Available", retitled "a platform-supplied substitute implementation is just Available": `source` dropped.
  - "require succeeds…": `source` dropped from the fixture.
- `tests/application.test.ts`, "resolves Environment before the service graph…": the map moves to `start`'s `platform`, and `source` is dropped. Assertions unchanged.
- `tests/semantic-isolation.test.ts`, "application capability is not target capability (DoD 12, I15)": fixture-only, found during implementation and approved. Its shared helper moves the map to `start`'s `platform`, and its `Available` fixture drops `source`. Assertions and the semantic behavior tested are unchanged.

## Try it

```console
$ pnpm install
$ pnpm test        # 23 files, 332 tests
$ pnpm typecheck
$ pnpm build
```

`tests/platform.test.ts` covers the supply point, the lifetime invariant on every route and failure path, isolation between starts, and the reference platform. `tests/default-services.test.ts` covers precedence. `tests/exports.test.ts` pins the primitive namespaces' runtime exports. `tests/architecture.test.ts` enforces host independence.

## Not in v0.6

- No platform packages: no Node, browser, server, worker or native platform.
- No platform composition, registry, discovery or detection, and no capability provenance or introspection.
- No capability vocabulary or requirement analysis, and no change to `Semantic`: what a semantic "target" denotes is still open (L6, v0.7).
- No SSR, hydration, HMR, request scope, rendering, PORT integration or tooling.
- No MESH adapter change. Initializing the MESH engine outside Node is still open (L7).
