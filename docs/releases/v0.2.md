# NEXUS v0.2.0 release notes

*Released 2026-09-26.*

v0.2 connects NEXUS to MESH. A NEXUS application renders a selector's value through MESH v0.5's runtime into a render tree, and a user event on that tree becomes a command intent. The intent reaches a NEXUS command through an explicit binding. Tests prove the whole loop in Node against MESH's own slice program and the published `@valancex/mesh-runtime@0.5.0`.

NEXUS core, the nine primitives, doesn't depend on MESH. The single integration boundary is the host adapter in `src/mesh/`, exported as `Mesh`, and a test enforces that boundary.

## Highlights

- **The MESH host adapter,** `Mesh.host({ program, scope, commands })`:
  - `render` renders the scope selector's current value into a `Render`;
  - `renders` gives one render per future commit;
  - `dispatch(render, handler, payload)` turns an event into a command intent and runs the bound command.

  `Mesh.bind(command, toInput)` is the translation boundary from intent arguments to command input, and `Command.invoke` validates the result. See [ARCHITECTURE §15](../ARCHITECTURE.md#15-mesh-host-adapter).
- **Four normative invariants:**
  - **M1:** `dispatch` uses exactly the `Render` it's given. A late event acts on the data the user saw, not on newer state.
  - **M2:** the adapter keeps no render registry or cache.
  - **M3:** only explicit bindings reach commands; anything else is `UnmappedCommand`.
  - **M4:** only the MESH runtime is a dependency. The compiler is used at build and test time only.
- **A defined error taxonomy.**
  - Typed failures: `MeshDiagnostics` (MESH rejected the input), `UnmappedCommand`, `CommandValidationError`, and the command's own errors.
  - Defects: a throwing binding and runtime or package faults.
- **`renders` lifecycle.** It emits future commits only, in commit order. A render diagnostic fails and ends the stream. It ends normally when the state's owning scope closes.
- **State lifecycle fix.** `State.changes`, and every selector derived from it, now completes when the state's owning scope closes, as `state.md` always documented.
- **Architecture checks.** A static test enforces the import boundaries:
  - core never imports the adapter or any MESH package;
  - the package entry reaches MESH only through the adapter;
  - the adapter never imports the compiler;
  - there are no PORT imports, and no MESH imports in `examples/`.
- **CI** runs typecheck, test and build on Node 22 and 24.

## Try it

v0.2 isn't published to npm. From a clone:

```console
$ pnpm install
$ pnpm test        # 13 files, 63 tests, including the MESH slice
$ pnpm build
```

`tests/mesh.test.ts` is a complete worked example: it compiles the slice, renders it, dispatches clicks and maps intents to commands.

## Upgrading from v0.1

- **The package is renamed** from `@valence/nexus` to `@valancex/nexus`.
- **Node 22 or later is required** (`engines.node`). `@valancex/mesh-runtime` needs it.
- **New dependency:** `@valancex/mesh-runtime@^0.5.0`.
- **`State.changes` now completes when its scope closes.** A subscriber that relied on it never ending sees a normal end instead. No API changed.
- **New public namespace: `Mesh`.** The nine primitives' public types are unchanged.

## Known limitations

The v0.2 architectural audit found these in the v0.1 core. They're planned for v0.3 (see the [v0.3 outline](https://github.com/ValanceX/Nexus/blob/nexus-v0.3/docs/superpowers/specs/2026-09-26-nexus-v0.3-outline.md) on the `nexus-v0.3` branch):
- `Event.subscribe` streams don't end on `Application.shutdown`.
- `RunningApplication.runtime` exposes its scope and the service `Context`. Closing the scope, or calling `Runtime.shutdown` on the handle, ends the runtime while the status still says `Running`.
- There is no first-class way to create application-owned `State`. v0.2's tests use `Scope.extend(State.create(...), running.runtime.scope)`, and that surface is scheduled to become internal.
- `Runtime.run`'s Promise rejects with Effect's failure wrapper. Non-Effect callers that need the typed error must run `Effect.exit` inside `run`.
- Some primitive docs' data models don't match the exported types. v0.3 reconciles them.
