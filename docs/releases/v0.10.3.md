# NEXUS v0.10.3 release notes

*Prepared 2026-10-05. Not yet released: a pushed `v0.10.3` tag publishes it (see `.github/workflows/release.yml`), after review.*

v0.10.3 is a patch release. It makes `@valancex/mesh-runtime` a **peer dependency** of NEXUS instead of a dependency, so an application has exactly one MESH runtime, the one it supplies. It changes no NEXUS API or behavior, and no source.

## Why

v0.10.1 and v0.10.2 each moved NEXUS's `@valancex/mesh-runtime` dependency to the application's MESH line (`^0.7.0`, then `^0.8.0`). Under 0.x semver a caret range admits one minor only, so an application on MESH v0.9 would have received a second, private v0.8 runtime inside `Mesh.host`. In a browser, the application's `init()` initializes only the runtime it imports, so NEXUS's own copy was never initialized and the first render failed with `call init() with the URL of mesh-runtime.wasm before the first render` (Node loads each copy itself, so SSR hid the problem). A peer dependency lets the package manager share the application's copy.

## Changes

- **`@valancex/mesh-runtime` is a peer dependency, `^0.8.0 || ^0.9.0`** (was a dependency, `^0.8.0`). NEXUS only calls `render` and `dispatch` and passes the `Render` through. MESH v0.9 changes neither (it adds the compiler's `compileProgram`). The full suite (494 tests) passes against the v0.8.0 runtime and against v0.9.0.
- **Development dependency:** `@valancex/mesh-runtime` `^0.9.0`, for NEXUS's own build and tests.
- **`tests/mesh-runtime-compat.test.ts`** now pins the boundary: the runtime is not a dependency, the peer range admits the installed runtime, and the lockfile resolves exactly one.

## Compatibility

- **No API or semantic change.** `State`, `values`, FiberRef isolation, `Running` and the application lifecycle are untouched.
- **Install:** an application that uses `Mesh.host` must have `@valancex/mesh-runtime` (`^0.8.0` or `^0.9.0`) in its own dependencies. pnpm and npm 7+ install missing peers by default; a project that disables that must add it.
- **MESH:** v0.8 and v0.9. An application on MESH v0.7 must stay on NEXUS v0.10.1.
- **PORT:** Web 0.2.4 declares `@valancex/mesh-runtime` `^0.6.0 || ^0.7.0 || ^0.8.0 || ^0.9.0`; Web 0.2.3 declares up to `^0.8.0`, so with MESH v0.9 it reports an unmet peer (a warning in pnpm), which does not affect NEXUS.
- **Evidence:** a clean pnpm project installing the packed NEXUS and `@valancex/mesh-runtime@0.9.0` resolves one runtime, and NEXUS and the application load the same module; the VALANCE tracer's Chromium test (hydration and real clicks) passes on that graph.
