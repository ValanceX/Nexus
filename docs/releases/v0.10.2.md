# NEXUS v0.10.2 release notes

*Released 2026-10-04 (`v0.10.2`).*

v0.10.2 is a patch release. It moves NEXUS to MESH v0.8's runtime, so an application on MESH v0.8 has one MESH runtime. It changes no NEXUS API or behavior. It is the same change v0.10.1 made for MESH v0.7.

## Changes

- **`@valancex/mesh-runtime` `^0.8.0`** (was `^0.7.0`). Under 0.x semver, `^0.7.0` excludes 0.8. So an application using MESH v0.8 would get a second, v0.7 runtime inside NEXUS's `Mesh.host`, and in a browser `init()` initializes only the runtime the application imports.
  - The adapter calls only `render` and `dispatch`, and passes the `Render` through. MESH v0.8 changed neither: it adds one operation, `declaredEvents`, which NEXUS does not use, and leaves `render-v1`, `template-v1` and the manifest format unchanged.
  - The whole suite passes unchanged (494 tests). The existing `tests/mesh-runtime-compat.test.ts` pins the boundary: the declared range admits the installed runtime, and the lockfile resolves exactly one (0.8.0).
- **Development dependency:** `@valancex/mesh-compiler` `^0.8.0`.

## Compatibility

- **No API or semantic change.** `State`, `values`, FiberRef isolation, `Running` and the application lifecycle are untouched.
- **MESH:** v0.8. Programs compiled by MESH v0.7 run unchanged. An application that stays on MESH v0.7 must stay on NEXUS v0.10.1.
- **PORT:** Web 0.2.3 declares `@valancex/mesh-runtime` `^0.6.0 || ^0.7.0 || ^0.8.0`, so it takes the one runtime NEXUS now depends on.
