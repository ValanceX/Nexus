# NEXUS v0.10.1 release notes

*Released 2026-10-02.* A pushed `v0.10.1` tag publishes it (see `.github/workflows/release.yml`).

v0.10.1 is a patch release. It moves NEXUS to MESH v0.7's runtime, so an application on MESH v0.7 has one MESH runtime. It changes no NEXUS API or behavior. It is the same change v0.8.1 made for MESH v0.6.

## Changes

- **`@valancex/mesh-runtime` `^0.7.0`** (was `^0.6.0`). Under 0.x semver, `^0.6.0` excludes 0.7. So an application using MESH v0.7 got a second, v0.6 runtime inside NEXUS's `Mesh.host`. In a browser, `init()` initializes the runtime the application imports, and the copy NEXUS renders with was never initialized: `@valancex/mesh-runtime: call init() with the URL of mesh-runtime.wasm before the first render`.
  - The adapter calls only `render` and `dispatch`, and passes the `Render` through. MESH v0.7 did not change either, nor render-v1 or template-v1; a program with no `mesh-if` or `mesh-each` renders exactly as in v0.6.
  - The whole suite passes unchanged (492 tests).
  - A new test file, `tests/mesh-runtime-compat.test.ts`, pins the boundary: the declared range admits the installed runtime and the lockfile resolves exactly one; and a host passes through v0.7's keyed `mesh-each` render, an item keeping its key across reorder, insertion and removal.
- **Development dependency:** `@valancex/mesh-compiler` `^0.7.0`.

## Compatibility

- **No API or semantic change.** `State`, `values`, FiberRef isolation, `Running` and the application lifecycle are untouched.
- **MESH:** v0.7. Programs compiled by MESH v0.6 run unchanged. An application that stays on MESH v0.6 must stay on NEXUS v0.10.0 (as v0.8.1 did for v0.5).
- **PORT:** Web 0.2.2 declares `@valancex/mesh-runtime` `^0.6.0 || ^0.7.0`, so it takes the one runtime NEXUS now depends on.
