# NEXUS v0.8.0 release notes

*Released 2026-09-27.*

v0.8 establishes **application semantics** for capability requirements:
- what part of an application owns a requirement;
- what "an application's requirements" means;
- how the requirements of an application's parts combine.

It does this without coupling runtime execution to static analysis. It is a **non-breaking** release with **no public API change**. It adds exact meanings, tests that pin them, and documentation.

## Highlights

- **Units own requirements.** A requirement belongs to a *unit*, a part of the application that NEXUS executes as a whole:
  - **the start unit**, the application's service graph build. Without a capability it needs, `start` fails with `ServiceGraphFailed`;
  - **an admitted unit**, an effect run through the runtime (typically a command). Without a capability it needs, only that effect fails.

  Each unit is described by one standalone `Semantic` declaration. No primitive value, definition, `Layer` or start option carries a requirement.
- **Necessity is not the union.**
  - The application's *necessity* is its start unit's requirement.
  - The union over the units a context describes is its *requirement set*: some described unit can't work without each member.
  - An incompatible command never means the application can't start.
- **An application context describes one composition.** A command that reaches a capability through a service requires it only when the application composes an implementation that does. Different compositions are different contexts.
- **A context is not an inventory.** It contains the units its producer chose to describe. Nothing implies it lists every unit, and everything derived from it is relative to those units.
- **Declaration ids are local to their context.** Relating a unit to a `Command`, an `Application` or any other primitive is the producer's or tooling's concern. NEXUS defines no mapping and no convention.
- **The aggregation is a contract, not an API.** The requirement set is the distinct ids in first-occurrence order, with every occurrence kept.
  - Completeness is `complete` only if every unit is. An undeclared unit counts as partial and empty.
  - The classification is incompatible over opaque over supported, which equals the classification of one declaration carrying the union.

  `Semantic` doesn't export it. A test-local helper pins it, exhaustively.
- **Four things stay separate:** start-unit necessity, the application requirement set, runtime capability resolution, and the static compatibility verdict. A verdict never changes runtime behavior.

## Decided, and documented

- L2 is closed: declarations stay canonical and standalone (D17 confirmed), and NEXUS attaches no fact to a primitive value.
- No capability provenance is added. The declaration id says which unit, and the optional spans say where.
- Optional capability use remains outside the requirement model.

## Compatibility and migration

**Nothing to migrate.** No public type, value, diagnostic code, message, rejection or behavior changes:
- the 11 entry namespaces, the primitive export pin, and `Semantic`'s 35 exports and 2 runtime values are unchanged;
- `src/` is unchanged from v0.7.0;
- no existing test was modified.

A v0.7 context with one "whole-application" declaration is still valid, and is a one-unit context.

## Tests

24 new tests in one new file, `tests/application-semantics.test.ts`. The total is 390 tests in 27 files, up from 366 in 26.
- **Characterizations (4):** one command under two compositions; two compositions as two contexts; overlapping units accepted and undetected; a second declaration of one unit rejected.
- **The aggregation (6):**
  - exhaustive equivalence with the union's classification (7,380 cases);
  - the partial-empty counter-check;
  - order, duplicates, partial units, and the empty context.
- **Units in the lifecycle (4):**
  - start-unit necessity, and admitted-unit isolation;
  - an incompatible admitted unit leaving the application starting;
  - resolution stays the `Layer`'s.
- **Independence and no attachment (10):**
  - `Command.define` and `Application.define` add no field, and `ApplicationDefinition` is exactly `{ name, runtime }`;
  - start and resolution are unaffected by every classification × `Layer` state;
  - a statically incompatible unit still runs where the capability is supplied.

Nine deliberate breaks were each caught and then reverted. The implementation plan's "As built" section lists them.

## Not in v0.8

- Any `src/` change.
- Requirement fields, metadata, decorators or annotations on primitives, definitions, `Layer`s or start options.
- A registry, or an inventory of units, commands or services.
- Discovery, and source-, type- or runtime-derived requirement capture.
- Enforcement, or start-time or dispatch-time gating.
- An exported aggregate (O11), a start-unit kind (O12), a completeness claim for contexts (O13), or containment, "uses" relations or inheritance (O14).
- Capability provenance (O3), optional-use facts (O10), a serialized format (O9), a domain tag (O8), or public conformance (O7).
- A PORT binding or PORT dependency (L1); MESH changes.
