# NEXUS v0.11.0 release notes

*Released 2026-10-09 (`v0.11.0`).*

v0.11.0 is a minor release. It adds one exported name family, `Runtime.Refusal`, so that a refusal can be recognized without reading its message. It changes no existing behavior, and it does not change how any call fails.

## Why

When a handle is misused, or used after termination has begun, NEXUS dies with a defect instead of returning a typed failure: using a handle after termination began is misuse, and an `E` channel on every `run` for it would make each caller handle what it cannot fix. That decision stands. But a command that races a shutdown is an ordinary event on a real page, and the only way to tell this defect from a bug was to match the text `NEXUS: ...`. The defect now has a stable identity.

## Changes

- **`Runtime.Refusal`**, an `Error` with a `code`: `"terminating"` (termination has been requested; no new work is admitted), `"not-a-runtime"` (a handle NEXUS didn't make), or `"not-an-application"` (the same, for an application handle). Messages are unchanged.
- **`Runtime.isRefusal(value)`** recognizes one, by its shape and not its class, so it works when two copies of the package are installed. Read it from a `Cause` with `Cause.dieOption`.
- **`Runtime.RefusalCode`**, the type of the codes.
- **The rule for error identity:** a thrown or dying error carries `code`; a typed failure in the `E` channel carries `_tag`. It is written in [primitives/runtime.md](../primitives/runtime.md).
- **Documentation, no behavior change:** [primitives/runtime.md](../primitives/runtime.md) now says that termination does **not** wait for effects started with `Runtime.run` or `Runtime.runFork` (it closes the runtime's scope while they run, so a `Resource` they use can be released under them), and that only work NEXUS itself admitted, such as an application-owned `State` being created, is waited for. A test pins it. The `State` example no longer uses a schema `State.create` cannot accept (`Schema.OptionFromNullOr`; it uses `OptionFromSelf`).
- **[API stability](../stability.md):** what each public surface promises, and the tiers (stable, unreleased, provisional, internal).

## Compatibility

- **API:** additive. No export is removed or changed.
- **Behavior:** the same calls fail in the same places with the same messages and the same `Cause` shape (a die). What differs is the class of the dying value: it is an `Error` whose prototype is `Refusal`. `error instanceof Error` and `String(error)` (`Error: NEXUS: ...`) are unchanged; `error.constructor.name` is now `Refusal`.
- **Install:** unchanged. `@valancex/mesh-runtime` stays a peer dependency, `^0.8.0 || ^0.9.0`.
- **MESH, PORT, VALANCE:** no change is needed. VALANCE can use `isRefusal` for its own refusals once it depends on this version.
- **Evidence:** 496 tests, typecheck and build pass; the packed tarball installed in a clean project exposes `Runtime.Refusal`, `Runtime.isRefusal` and the refusal codes.
