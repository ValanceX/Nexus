## Global constraints

- **Frozen scope.** Nothing from the outline's non-goals (§11): no source reading, no IR, no optimizer, no planner, no discovery, no tooling (CLI, LSP, editor, dev server, build integration), no PORT, no MESH change, no lifecycle change, no primitive change, no taxonomy or shipped profile, no v0.3 deferrals (O8–O10), no npm publishing.
- **Additive only.** No existing file under `src/` changes except `src/index.ts`, which gains exactly one line (Task 1). Every existing test passes unmodified. The only existing test file that changes is `tests/architecture.test.ts`, and only by addition (D13).
- **The module is a leaf** (D13, I18). Files under `src/semantic/` import nothing: no `effect`, no `node:*`, no `@valancex/*`, and no `src/` module outside `src/semantic/`. Relative imports between files inside `src/semantic/` are allowed, but the plan expects one file.
- **Plain data everywhere** (C1, I13). Every public type of the module is built only from `string`, `number`, `boolean`, string-literal unions, `ReadonlyArray` and readonly object types of these. No class, no `Error`, no function-typed field, no `Map`/`Set`, no `symbol`, no `bigint`, no `Date`.
- **Outputs are fresh.** The analysis never returns an input object by reference. Every span in an output is a new `{ source, start, end }` copied field by field, so extra properties on an input span never reach an output (I17: never widened), and output never aliases input.
- **No `undefined`-valued keys in output.** Optional output parts are omitted, never set to `undefined`, so a JSON round trip is deeply equal (I13).
- **The analysis never invokes a value from its input.** It reads the fields C1–C7 name and nothing else. It never calls, `await`s, iterates with a custom iterator beyond array indexing, or spreads an input value. (Accessor properties on input objects are the caller's code; see "Risks".)
- **Tests assert on data, never on message text** (DoD 7): codes, severities, subjects, spans, verdicts and classifications. `message` and `notes` are asserted only to be non-empty strings.
- **Conventions:** `.js` extensions on relative imports; no `any`; `_tag`ged plain-object unions for results; no `Effect.Do` in this module, because it has no Effect (D11).

## The public model (the shape Task 2 writes)

Names are the plan's; the outline's italic working terms map as noted.

```ts
// C2
export interface Span { readonly source: string; readonly start: number; readonly end: number }

// C4: one entry of a target-requirements fact
export interface Requirement { readonly capability: string; readonly provenance?: Span }

// C3/C4: the only v0.4 property
export interface TargetRequirements {
  readonly completeness: "complete" | "partial";
  readonly capabilities: ReadonlyArray<Requirement>;
}

// C1
export interface Declaration {
  readonly id: string;                         // semantic identity (D4)
  readonly name?: string;                      // display name, never identity
  readonly provenance?: Span;
  readonly requirements?: TargetRequirements;  // absent = unknown (I14)
}

// C4
export interface TargetProfile {
  readonly name: string;
  readonly provenance?: Span;
  readonly provided: ReadonlyArray<string>;
  readonly notProvided: ReadonlyArray<string>;
}

export type Property = "target-requirements";
export type RequiredFact = "target-compatibility";

// C7 input
export interface AnalysisContext {
  readonly declarations: ReadonlyArray<Declaration>;
  readonly profile: TargetProfile;
  readonly require?: ReadonlyArray<RequiredFact>;
}

// C4: verdict with cause; carries every fact a diagnostic asserts (C5)
export type Verdict =
  | { readonly _tag: "Compatible" }
  | { readonly _tag: "Incompatible"; readonly notProvided: ReadonlyArray<string> }
  | { readonly _tag: "Undetermined"; readonly cause: "operation"; readonly requirements: "undeclared" | "partial" }
  | { readonly _tag: "Undetermined"; readonly cause: "target"; readonly undecided: ReadonlyArray<string> };

export type Classification = "supported" | "opaque" | "incompatible";

export interface OperationResult {
  readonly id: string;
  readonly known: ReadonlyArray<Property>;
  readonly verdict: Verdict;
  readonly classification: Classification;
}

// C6
export type DiagnosticCode =
  | "nexus-incompatible-target-capability"
  | "nexus-opaque-operation"
  | "nexus-undetermined-target-capability";
export type Severity = "warning" | "error";
export type Location = { readonly _tag: "Span"; readonly span: Span } | { readonly _tag: "Unlocated" };
export interface RelatedSpan { readonly span: Span; readonly label: string }
export interface Diagnostic {
  readonly code: DiagnosticCode;
  readonly severity: Severity;
  readonly message: string;
  readonly location: Location;
  readonly subject: string;
  readonly related: ReadonlyArray<RelatedSpan>;
  readonly notes: ReadonlyArray<string>;
}

// C7 output
export type RejectionReason =
  | "duplicate-identity" | "missing-identity" | "invalid-span"
  | "empty-capability" | "conflicting-decision";
export interface RejectionIssue { readonly reason: RejectionReason; readonly path: ReadonlyArray<string | number> }

export type AnalysisOutcome =
  | {
      readonly _tag: "Analyzed";
      readonly properties: ReadonlyArray<Property>;
      readonly required: ReadonlyArray<RequiredFact>;
      readonly profile: string;
      readonly operations: ReadonlyArray<OperationResult>;
      readonly diagnostics: ReadonlyArray<Diagnostic>;
    }
  | { readonly _tag: "Rejected"; readonly issues: ReadonlyArray<RejectionIssue> };

export const analyze: (context: AnalysisContext) => AnalysisOutcome;
```

`related` and `notes` are always present, possibly empty, so a consumer never distinguishes "absent" from "empty". `Unlocated` is explicit (C2).

## The algorithm (Tasks 3–5 implement it)

For a well-formed context, for each declaration in order:
1. `known` is `["target-requirements"]` exactly when `requirements` is present, else `[]`.
2. **Verdict** (C4), with `ids` the distinct capability ids in declaration order:
   - requirements present and some id is in `profile.notProvided` → `Incompatible`, `notProvided` = those ids in order;
   - else requirements absent → `Undetermined`, operation cause, `"undeclared"`;
   - else partial → `Undetermined`, operation cause, `"partial"`;
   - else some id in neither list → `Undetermined`, target cause, `undecided` = those ids;
   - else → `Compatible` (this includes the empty complete set).

   The incompatible check runs first, so a partial set with a not-provided id is incompatible (DoD 4), and the operation-side check runs before the target-side one (C4: "if both apply, the cause is operation-side").
3. **Classification** maps the verdict one to one (C5).
4. **Emission** (C5 rules 1–4): `Incompatible` → one error; `Compatible` → nothing; `Undetermined` → one warning only when `require` contains `"target-compatibility"`, with the code chosen by cause.
5. **Location**: `{ _tag: "Span", span: copy(declaration.provenance) }` if present, else `{ _tag: "Unlocated" }`.
6. **Related spans** (C6's table): for an error, every requirement occurrence whose id is not provided and that has provenance, labelled `"requirement declared here"`, then the profile's provenance if any, labelled `"target profile declared here"`; for the target-side warning, every undecided requirement occurrence with provenance; for the operation-side warning, none.
7. **Notes**: prose carrying C6's "notes must state" column, built from the verdict data only.

Rejection (D6) is checked over the whole context first. If any issue exists, the result is `Rejected` with every issue, and no operation is analyzed. The checks, each producing issues in input order:
- `missing-identity`: `id` is not a non-empty string;
- `duplicate-identity`: an `id` equal to an earlier declaration's (reported at the later one);
- `invalid-span`: any span (declaration, requirement or profile) with `end < start` or an empty `source`;
- `empty-capability`: an empty string in any requirement's `capability`, `provided` or `notProvided`;
- `conflicting-decision`: an id in both `provided` and `notProvided` (reported once per id).

### Task 5: Diagnostic emission (C5 rules, C6; I12, I17; DoD 4, 5, 6)

**Files:** `src/semantic/index.ts`; `tests/semantic.test.ts`.

**Tests, written first:**
- **Emission matrix:** every verdict case × `require` empty / `["target-compatibility"]`. Assert the exact list of `(code, severity, subject)`:
  - incompatible → one `nexus-incompatible-target-capability`, `error`, in both columns (DoD 4);
  - supported → none, in both columns (DoD 5);
  - opaque, operation cause → none / one `nexus-opaque-operation`, `warning`;
  - opaque, target cause → none / one `nexus-undetermined-target-capability`, `warning`.
- **No error without proof** (I12): across the matrix, `severity: "error"` appears only for incompatible verdicts.
- **At most one diagnostic per operation,** and diagnostics follow declaration order (C6).
- **Provenance** (DoD 6):
  - the primary span deep-equals the declaration's span;
  - related spans for an error: exactly the not-provided requirements' provenance, in order, then the profile's; for a target-side warning: exactly the undecided requirements'; for an operation-side warning: none;
  - a declaration with no span gives `location: { _tag: "Unlocated" }` and its `subject`;
  - **no fabricated span:** the set of spans in all diagnostics is a subset of the spans in the input (compared by value);
  - **not widened:** an input span with an extra property yields an output span with exactly `source`, `start`, `end`;
  - **not aliased:** mutating the input after analysis doesn't change the outcome.
- **Notes carry the facts** (C6), asserted only as non-empty strings; the facts themselves are asserted on the verdict (C5: "the result is authoritative").

**Commit:** `feat(semantic): emit nexus- diagnostics from classifications`.

## Risks (plan-level; the outline's R1–R6 still apply)

- **Accessor properties on input.** A caller can pass an object with a getter, whose code runs when the analysis reads the field. Reading a declared field is not "executing the operation"; the getter is the caller's code, not the operation's implementation. The plan documents this in the reference page and doesn't defend against it (a defensive copy would itself invoke the getter). Task 7's execution test uses ordinary data objects.
- **Type-level tests can pass vacuously.** A misspelled `@ts-expect-error` target, or an `expectTypeOf` that resolves to `any`, proves nothing. Task 9's breaks include two that only the type tests catch, to show they bite.
- **The architecture test's `core` set grows.** `src/semantic/` falls into the existing "core" bucket. That is correct (it must not import MESH either), but the new leaf rule is strictly stronger, and both are kept.
