# NEXUS v0.6 Runtime / Platform Boundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Revision 3 (the fifth amendment, approved during Task 7). Revision 2: options-object `start`; the C15 lifetime invariant tightened. Architecture approved in substance. **Do not execute** until implementation is approved.

**Goal:** Make `options.platform` of `Application.start(app, options?)` the single place an application's environment is supplied. Remove the three public items that put environment knowledge in NEXUS (`ApplicationDefinition.environment`, `CapabilitySource`/`source`, `Capability.tag`). Enforce host independence of `src/`. Change no lifecycle, admission, State, Selector, Command, Event, Service, Resource, Runtime, Semantic or MESH behavior.

**Architecture:**
- `Application.Platform` is a type alias, `Layer<Capability.EnvironmentShape, unknown, never>`. `Application.StartOptions` is `{ readonly platform?: Platform }`, exactly, with no other field (D42).
- `start(app, options?)` provides `Layer.provideMerge(definition.runtime, options?.platform ?? empty)` to the application-owned runtime scope, exactly where v0.5 built `provideMerge(definition.runtime, EnvironmentLive(...))`. So build order, release order and failure handling come from the existing `Runtime.make` path unchanged.
- `RunningApplication.environment` is read from the built context.
- The first platform is a reference test platform under `tests/platform/`.

**Tech stack:** TypeScript 5.6 (strict, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`), Effect 3.22, Vitest 2, pnpm 10.

**Spec:** `docs/superpowers/specs/2026-09-27-nexus-v0.6-outline.md` (Revision 1). The outline wins wherever the two disagree.

## Global Constraints

- **The breaks are exactly three:** D31 (`ApplicationDefinition.environment`), D33 (`CapabilitySource`, `Available.source`) and D37 (`Capability.tag`). No other public item changes (outline E).

- **`StartOptions` has exactly one field, `platform`** (D42). Don't add, reserve or comment in any other field; a type test pins the shape.
- **The lifetime invariant (C15, I31):** the platform Layer is provided to the application-owned runtime scope, so the application's lifetime governs acquisition and release of platform resources. Tests pin the full order on both shutdown routes and on three failure paths. G3 (Task 3) must pass unchanged from Task 3 to the end.
