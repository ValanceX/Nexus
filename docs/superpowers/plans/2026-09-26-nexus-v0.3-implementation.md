# NEXUS v0.3 Implementation Plan: lifecycle, ownership and contract reconciliation

> **For agentic workers:** execute task by task, in order. Steps use checkbox (`- [ ]`) syntax. Each task ends green (`pnpm typecheck && pnpm test`) before the next starts. Write every test before the change it covers, and watch it fail first.

**Status:** implemented on `nexus-v0.3` (Tasks 0–8). Departures, results and evidence are under "As built" at the end.

**Spec:** `docs/superpowers/specs/2026-09-26-nexus-v0.3-outline.md`. Where this plan and the outline disagree, the outline wins, and the disagreement is a bug in the plan. The outline's labels are used throughout:
- the audit findings O1–O7;
- the new invariants N1–N4;
- the decisions D1–D5;
- the resolved questions Q1–Q3;
- the v0.2 invariants M1–M4.

**Goal:** make the ownership and lifecycle model NEXUS promises true in code (part A: O1–O4), and reconcile every primitive's documented contract with its implementation (part B: O5–O7). No new features.

**Tech stack:** as v0.2. TypeScript 5.9 (strict, NodeNext, `exactOptionalPropertyTypes`), Effect 3.22, Vitest 2.1, pnpm 10, Node 22 and 24.

## Global constraints

- **Frozen scope.** Nothing from the outline's non-goals:
  - no MESH host composition;
  - no non-Effect host support;
  - no PORT, renderer or browser work;
  - no capability probing;
  - no selector memoization;
  - no typed command outputs;
  - no package split;
  - no hot reload, runtime MPRX compilation or composite events;
  - no npm publishing;
  - no command registry;
  - no compatibility wrappers.
- **`src/mesh/` is not modified.** M1–M4 and the `renders` contract are untouched. `tests/mesh.test.ts` changes in exactly one line, the `runSlice` harness's `Team` creation (Task 5).
- **Locked v0.2 invariants stay true after every task:**
  - M1–M4;
  - the error taxonomy;
  - `renders`: future commits only, terminal on a diagnostic, and a normal end when its scope closes;
  - `State.changes` completes when its scope closes (F-A);
  - selectors are pure, and `combine` completes when either side does;
  - `Command.invoke` decodes before the handler runs;
  - import boundaries (test 9 and the architecture checks);
  - no PORT dependency;
  - the pinned MESH fixture;
  - packaging decision 8.
- **No new public error type** (Q2). No new public abstraction beyond:
  - D1's constructor, `Application.createState`;
  - D2's opaque `NexusRuntime`.
- **Internal machinery lives in non-exported modules.** Everything `src/index.ts` reaches through `export * as X from "./x/index.js"` is public. So:
  - `src/runtime/internal.ts` and `src/event/internal.ts` are new, and are imported only by core modules;
  - they are never re-exported;
  - test 9 already counts them as core.
- **Conventions:**
  - `Effect.Do` pipelines in `src/`;
  - `_tag`ged plain-object errors;
  - `.js` extensions on relative imports;
  - no `any`.
- **One refusal value.** Refusals caused by lifecycle misuse die with a plain `Error` whose message begins `"NEXUS:"`, created through one internal helper. It is not exported. Tests assert `Cause.isDie` and `Cause.failureOption` is `None`, never the error's class.

## Verified mechanisms (read-only probes, scratch build of `dffc7e5`, Effect 3.22)

| # | Mechanism | Result |
|---|---|---|
| M1 | A subscription ended with `Stream.interruptWhenDeferred` | Exits `Success` after delivering earlier events; a later `PubSub.publish` succeeds; a later subscription ends at once with no events |
| M2 | Traversing `Ref.get(ref)`'s own enumerable properties | The `Ref` isn't reachable. The `status` field can stay an `Effect` without exposing the status `Ref`. |
| M3 | A frozen null-prototype object registered in a module-private `WeakMap` | `Reflect.ownKeys` is `[]`; internal lookup works |
| M4 | `Stream.fromQueue(q)` after `Queue.shutdown(q)` on a `PubSub` subscription | Exits `Success`. Undelivered buffered events are dropped; a later `publish` succeeds. |

M4 is what lets Task 2 end every subscription, including raw `EventBusShape.subscribe` queues, without changing the public `EventBusShape` type.

## Part A: lifecycle and ownership closure (O1–O4)

### Task 1: Opaque `NexusRuntime`, and no public runtime shutdown (N3, D2; O3, part of O2)

**Files:**
- New `src/runtime/internal.ts`.
- `src/runtime/index.ts`.
- `src/application/index.ts`: only its call to `Runtime.shutdown`.
- `tests/runtime.test.ts`.

**Contract:**
- `NexusRuntime<R>` exposes nothing: no `scope`, `runtime` or `context`, under any key.
- `Runtime.run` and `Runtime.runFork` still execute against the service graph.
- `Runtime.shutdown` is not public.
- A standalone runtime ends when the `Scope` passed to `Runtime.make` closes.

**Approach:**
- **The handle type.** In `index.ts`:

  ```ts
  declare const NexusRuntimeTypeId: unique symbol;
  export interface NexusRuntime<in R> {
    readonly [NexusRuntimeTypeId]: (_: R) => void;
  }
  ```

  It is type-only: the symbol is a `declare const`, so it has no runtime value. It is contravariant in `R`, like Effect's `Runtime<in R>`, so every existing `Runtime.run(running.runtime, …)` call site infers exactly as before.
- **The internal record.** `internal.ts` holds a module-private `WeakMap<object, RuntimeRecord>`. Each record holds the Effect `Runtime`, the `CloseableScope`, and the fields Tasks 2–3 add.
  - `register(record)` returns `Object.freeze(Object.create(null))`, cast to `NexusRuntime<R>`, and stores the record under it.
  - `recordOf(handle)` returns `RuntimeRecord | undefined`.
  - The internal `terminate(handle)` for now just closes the scope, as `Runtime.shutdown` did. Task 3 extends it.
- **`Runtime.make`** builds exactly as today: layer, `EventBusLive` provide-merged, `LayerBuildFailed` mapping. It registers the record, and adds the caller-scope finalizer `terminate(handle)`, replacing today's bare `Scope.close`.
- **`Runtime.run` and `Runtime.runFork`** look up the record and run through its Effect `Runtime`. A handle with no record (forged, or from another copy of the module) is refused as a defect through the refusal helper. It never throws synchronously.
- **`Runtime.shutdown`** is deleted from `index.ts`. `Application`'s shutdown calls the internal `terminate`.

**Tests, written first, in `tests/runtime.test.ts`:**
- **Type level, compiled by `pnpm typecheck`:**
  - `// @ts-expect-error` on `handle.scope`, `handle.runtime` and `handle.context`;
  - `// @ts-expect-error` on `Runtime.shutdown`.
- **Runtime reflection:**
  - `Reflect.ownKeys(handle)` is `[]`;
  - a recursive walk over own keys, symbols included (depth ≤ 6), finds no value `v` for which any of these is true:
    - `Context.isContext(v)`;
    - `Scope.ScopeTypeId in v`;
    - `v` has both `runtimeFlags` and `fiberRefs` (an Effect `Runtime`).
- **Execution preserved:** `Runtime.run(handle, Effect.flatMap(Clock, (c) => …))` resolves through the service graph.
- **Standalone lifecycle:** a `Scope.make`, then `Scope.extend(Runtime.make(HeldLive), scope)`, then `Scope.close(scope)`. The resource is released.
- **A forged handle:** `Runtime.run(Object.freeze({}) as never, eff)` rejects, the effect's body never runs, and the cause is a die.

**Migrate:** `tests/runtime.test.ts:88-89` ("shutdown releases resources…"). It currently calls `Runtime.shutdown`. Replace that with an explicit `Scope.make`, `Scope.extend(Runtime.make(HeldLive), scope)` and `Scope.close(scope)`. The assertion (`released === true`) is unchanged.

**Must remain unchanged:** every other runtime test; `application.test.ts`; `vertical-slice.test.ts`; `mesh.test.ts`; `architecture.test.ts`.

**Depends on:** Task 0.

**Commit:** `feat(runtime): make NexusRuntime an opaque handle; remove public Runtime.shutdown`.

### Task 2: A closable Event bus (N1 for `Event.subscribe`, D4's mechanism; O1)

**Files:**
- New `src/event/internal.ts`.
- `src/event/index.ts`.
- `tests/event.test.ts`, adding tests only.

**Contract:**
- A bus can be *closed*. From then on it delivers nothing to any subscription, and every existing subscription ends normally.
- A subscription opened after closing ends immediately with no events.
- `publish` keeps succeeding (error channel `never`), reaching no subscriber.
- The public `EventBusShape` type and `Event.publish`/`Event.subscribe` signatures are unchanged.
- `EventBusLive` keeps its type, and now closes when its layer scope closes.

**Approach:**
- **Move the service tag.** `Context.GenericTag("nexus/EventBus")` moves from `index.ts` into `internal.ts`, and `index.ts` imports it back. It stays unexported publicly.
- **`makeBus` in `internal.ts`** is an `Effect` returning `{ shape: EventBusShape; close: Effect<void> }`. Internally it holds:
  - one `PubSub.unbounded<Envelope>()`;
  - a `closed` flag;
  - the set of live subscription queues;
  - a `Semaphore(1)` guarding the flag and the set.

  Its members behave as follows:
  - **`shape.publish`** is unchanged: `PubSub.publish(...).pipe(Effect.asVoid)`.
  - **`shape.subscribe`** (scoped) runs under the lock:
    - if the bus is closed, it returns a queue that is already shut down;
    - otherwise it calls `PubSub.subscribe`, adds the queue to the set, and adds a scope finalizer that removes it.
  - **`close`** runs under the lock: it sets `closed`, then calls `Queue.shutdown` on every live queue. It is idempotent.

  By M4, `Stream.fromQueue` over a shut-down queue ends with `Success`, and events still buffered are never delivered.
- **`EventBusLive`** becomes `Layer.scoped(EventBus, makeBus.pipe(Effect.tap(({ close }) => Effect.addFinalizer(() => close)), Effect.map(({ shape }) => shape)))`.
- **`Event.subscribe`** is unchanged in code: `Stream.fromQueue` over `bus.subscribe`.

**Tests, written first, in `tests/event.test.ts`** (bus built through `Layer.buildWithScope(EventBusLive, scope)`):
- After `close`, which is here the layer scope closing:
  - a running `Event.subscribe` consumer's fiber exits `Success`;
  - the events it collected are exactly those published before closing;
  - an event published after closing is never collected.
- A `publish` after closing exits `Success`.
- An `Event.subscribe` started after closing completes with an empty chunk within a bounded wait.
- A raw `bus.subscribe` queue, taken through `Effect.context<EventBusShape>()`, is shut down at closing.

**Must remain unchanged:** the three existing Event tests, including "rejects a malformed payload when validated against its schema". Under Q3 = B it tests the schema, which remains valid. Also the runtime test that reaches the bus through `Effect.context<Event.EventBusShape>()`.

**Depends on:** Task 0. It's independent of Task 1.

**Commit:** `feat(event): close the bus with its owner; end every subscription normally`.

### Task 3: Runtime termination order and admission (Q1, D4 ordering, standalone lifecycle; O1, O2)

**Files:** `src/runtime/internal.ts`, `src/runtime/index.ts`, `tests/runtime.test.ts`.

**Contract:**
- **Admission.** A runtime admits new work while live. Once its termination has begun, `Runtime.run`/`runFork` through its handle don't start the effect, and end as a defect with no typed error.
- **Termination order:**
  1. stop admitting;
  2. close the bus (D4);
  3. close the runtime scope, which releases resources and ends `State.changes` in that scope.
- **Idempotent and uninterruptible:** a second `terminate` waits for the first and returns when it's done.

**Approach:**
- **`RuntimeRecord` gains:**
  - `accepting: boolean`, a plain mutable field, because `run` is synchronous;
  - `admission: Semaphore(1)`;
  - `bus: { close }`;
  - `terminated: Deferred<void>`;
  - `claimed: boolean`.
- **`Runtime.make`** builds the bus with `makeBus` (Task 2). It provide-merges `Layer.succeed(EventBus, bus.shape)` in place of `EventBusLive`, so this runtime's bus is closed by `terminate`, not by the layer scope.
- **`terminate(handle)`**, run `Effect.uninterruptible`:
  - If `claimed` is already set, it awaits `terminated`.
  - Otherwise it claims, then:
    1. `admission.withPermits(1)(set accepting = false)`;
    2. `bus.close`;
    3. `Scope.close(scope, Exit.void)`;
    4. `Deferred.succeed(terminated)`.
- **`Runtime.run` / `runFork`:** if `accepting` is false, return `runPromise` / `runFork` of the refusal defect on Effect's default runtime. The user's effect is never passed to any runtime.
- **`admit(handle, effect)`** is internal, for Task 5. It runs `effect` under `admission.withPermits(1)` only if `accepting`, and otherwise dies with the refusal. Because `terminate` flips `accepting` under the same permit, `admit` and the start of termination are totally ordered.

**Tests, written first:**
- **Q1 on a standalone runtime** (closing the scope passed to `Runtime.make`):
  - afterwards, `Runtime.run(handle, Effect.sync(() => { ran = true }))` rejects, `ran` stays false, and `Runtime.isFiberFailure` holds with a die cause;
  - `Runtime.runFork(handle, …)`'s `Fiber.await` is a failure with `Cause.isDie`, and `Cause.failureOption` is `None`.
- **Refusal from the start of termination.** A layer resource whose `release` waits on a test-controlled `Deferred` holds the runtime in termination:
  - a `run` issued while it's held is refused;
  - after releasing the gate, the scope-close effect completes.
- **Order (D4, standalone).** One shared log records:
  - each delivery to an `Event.subscribe` consumer;
  - `"released"` from a layer resource's `release`.

  An effect admitted before closing publishes in a loop, with `Effect.yieldNow()` between publishes. After closing the scope, assert that no delivery entry follows `"released"`, that the consumer exited `Success`, and that none of the looping effect's publishes failed. Interrupt the loop at the end.
- **Idempotency:** a test imports `terminate` from `../src/runtime/internal.js` and runs it twice concurrently on one standalone runtime, then closes the owning scope. The layer resource is released exactly once, both calls return, and the scope's own finalizer is a no-op. (A standalone runtime has only one public termination route, its scope, so idempotency is exercised through the internal function.)

**Must remain unchanged:** every existing runtime test, including "feeds its own event bus…", which relies on the bus being provide-merged and reachable through `Effect.context`.

**Depends on:** Tasks 1 and 2.

**Commit:** `feat(runtime): refuse work after termination; close the bus before releasing resources`.

### Task 4: Application lifecycle integrity (N2, D3; O2)

**Files:** `src/application/index.ts`, and a new `tests/lifecycle.test.ts`.

**Contract** (N2, precisely):
- **Exactly two termination routes** for a started application: `Application.shutdown(running)`, and closing the caller's start scope. Both reach `Stopped`, release everything, and satisfy N1.
- **Status is monotonic.** It never returns to `Running`, and nothing is written after `Stopped`.
- **`shutdown` is idempotent and concurrency-safe:** it never fails, and every call returns at `Stopped`.
- **A failed start** is a typed `ServiceGraphFailed`. No handle is returned, and it isn't a route.
- **`RunningApplication` has no `shutdown` field.**

**Approach:**
- **Internal state.** A module-private `WeakMap<RunningApplication, AppRecord>` holds:
  - the status `Ref`, still read by the public `status: Effect<ApplicationStatus>` field, which is `Ref.get` (M2);
  - `stopped: Deferred<void>`;
  - the runtime handle.

  `RunningApplication` is frozen, with fields `status`, `runtime` and `environment` only.
- **`terminateApplication(record)`**, `Effect.uninterruptible`:
  - `Ref.modify` on status, atomically:
    - `Running` → `Stopping`, and this caller claims the termination;
    - `Stopping` → wait for `stopped`;
    - `Stopped` → return.
  - The claimer runs internal `terminate(handle)` (Task 3), sets `Stopped`, then `Deferred.succeed(stopped)`.
- **`Application.shutdown(running)`** is `terminateApplication(recordOf(running))`. A running application with no record (forged) is refused as a defect.
- **Route 2.** `Application.start` adds `Effect.addFinalizer(() => terminateApplication(record))` to the caller's scope after `Runtime.make`. Finalizers run in reverse order, so this runs first and does the full sequence. `Runtime.make`'s own finalizer then finds termination already claimed, and returns (Task 3).
- **Startup failure:** the path is unchanged (`Failed`, typed error, no handle).

**Tests, written first** (`tests/lifecycle.test.ts`; each application has a layer resource that counts releases):
- **Route 1:**
  - `shutdown` leads to `Stopped`, with exactly 1 release;
  - an `Event.subscribe` consumer forked through `running.runtime` before shutdown exits `Success` (P1's regression);
  - after it, `Runtime.run(running.runtime, …)` is refused (Q1), and so is `Runtime.runFork`.
- **Route 2** (P7's regression). Close the caller's start scope without calling `shutdown`:
  - a retained `running` reports `Stopped`;
  - exactly 1 release;
  - an `Event.subscribe` consumer forked before the close exits `Success`;
  - a following `Application.shutdown` returns immediately, and status stays `Stopped`.
- **Startup failure:**
  - `Effect.flip(start(broken))` yields `ServiceGraphFailed`, with no `RunningApplication`;
  - resources acquired before the failing layer are released by the time the caller's scope closes.

  (The type-level check that `ApplicationInitError` has exactly one variant is Task 6's, which removes the second variant.)
- **Repeated shutdown:** shutdown twice. A status sampler (a forked `Effect.forever` of `Application.status`, `Effect.yieldNow`, appending changes) never records `Stopping` after `Stopped`.
- **Concurrent shutdown:**
  - 10 concurrent `Application.shutdown` calls, plus a concurrent close of the caller's scope, via `Effect.all(…, { concurrency: "unbounded" })`;
  - exactly 1 release;
  - every call returns after status is `Stopped`;
  - the sampler shows a monotonic sequence;
  - the whole case repeats 100 times.
- **In `Stopping`:** a gated release, as in Task 3, holds the application in `Stopping`. Assert:
  - `Application.status` is `Stopping`;
  - `Runtime.run` and `Runtime.runFork` through the handle are refused as defects;
  - after opening the gate, the status is `Stopped`.
- **Structure:** `// @ts-expect-error running.shutdown`, and `Reflect.ownKeys(running)` is exactly `status`, `runtime` and `environment`.

**Must remain unchanged:** all of `application.test.ts` (four tests, including "transitions to Stopped and releases resources on shutdown"); `vertical-slice.test.ts`.

**Depends on:** Task 3.

**Commit:** `feat(application): two termination routes, monotonic status, idempotent shutdown`.

### Task 5: Application-owned State (D1, Q2 = A; O4), and the harness migration

**Files:**
- `src/application/index.ts`, adding `createState`.
- `tests/lifecycle.test.ts`.
- `tests/state.test.ts:104`.
- `tests/mesh.test.ts:105`, that one line only.

**Contract:**
- The signature is `Application.createState<R, A>(running: RunningApplication<R>, schema: Schema.Schema<A>, initial: A): Effect.Effect<StateHandle<A>, StateInitError>`, generic in `R` like `Application.shutdown` and `Application.status`. It has no `Scope` requirement, and its error channel is exactly `StateInitError`.
- The `State` is owned by the application: it lives in the application runtime's scope. On termination by either route, its `changes`, and everything derived from it, end normally.
- **Admission only while `Running`.**
  - Otherwise, including when construction loses a race with termination, it creates no `State` and dies (Q2 = A: a defect, with `Cause.failureOption` `None`).
  - There is no third outcome.
- It's reached only through its handle. Nothing is registered in any context.

**Approach:**
- `createState` resolves the `AppRecord`; a missing record dies with the refusal.
- It returns `admit(handle, Scope.extend(State.create(schema, initial), scopeOf(handle)))`, using Task 3's `admit`. `scopeOf` is internal.
- `admit` holds the permit that `terminate` needs to stop admitting, so the construction either completes, with the state's finalizer registered in the still-open scope, before termination begins, or it sees `accepting = false` and dies.
- `State.create`'s `StateInitError` passes through unchanged.

**Tests, written first, in `tests/lifecycle.test.ts`:**
- **While `Running`:**
  - it returns a `StateHandle`;
  - a forked consumer of its `changes`, and of a `Selector.define` over it, both exit `Success` after `shutdown`, and separately after route 2.
- **An invalid initial value:** `Effect.flip` yields `{ _tag: "InitialValueInvalid" }`.
- **Type level:** `expectTypeOf<Effect.Effect.Error<ReturnType<typeof Application.createState<number>>>>().toEqualTypeOf<StateInitError>()`, and the same for its requirements, which are `never`.
- **In `Stopping`** (gated release) **and after `Stopped`:** the effect's `Exit` is a failure, with `Cause.isDie` true and `Cause.failureOption` `None`.
- **The race.** Repeat 200 times: start an application, then run `createState` and `Application.shutdown` concurrently. In every iteration, exactly one of these holds:
  - a `StateHandle` came back, and a consumer started on its `changes` exits `Success` within a bounded wait;
  - the exit is a die.

  Run the same race against route 2.

**Migrate:**
- `tests/state.test.ts:104`: `Scope.extend(State.create(Counter, …), running.runtime.scope)` becomes `Application.createState(running, Counter, …)`. The test's assertions are unchanged.
- `tests/mesh.test.ts:105`: `Scope.extend(Nexus.State.create(Team, initialTeam), running.runtime.scope)` becomes `Nexus.Application.createState(running, Team, initialTeam)`. No other line of `mesh.test.ts` changes.

**Must remain unchanged:** MESH tests 1–9 (their bodies and assertions), the F-A scope-owned test (`tests/state.test.ts:81`), and `src/mesh/`.

**Depends on:** Task 4.

**Commit:** `feat(application): application-owned State through Application.createState`.

### Release-gate audit: defects found and fixed

The independent release-gate audit of `ce37ee2` found two contract defects. Both are fixed in the commit that follows this record.

- **B1. New work admitted during `Stopping`.** Violated N2 and D1.
  - **The defect:** termination claimed and set `Stopping` first, and only then waited for the admission permit to stop admitting. `Runtime.run`/`runFork` checked only `accepting`. So while an admitted `createState` held the permit across a yield (a schema that decodes asynchronously), the application read `Stopping` and still admitted work. The `State` also came into existence after termination had begun.
  - **Probe P-A**, both routes: status `Stopping`, and a `runFork` issued then ran.
  - **The fix,** option (b) of the audit: `Running → Stopping` and the end of admission are one atomic step under the admission permit.
    - `terminateLifecycle` runs the owner's `onBegin` hook (an application's `Stopping`) and `accepting = false` inside the permit. Then it closes the bus, closes the scope, and runs `onEnd` (`Stopped`) before any caller returns.
    - `Application.start` attaches those hooks to its runtime. Route 1 (`Application.shutdown`) and route 2 (the runtime's own finalizer on the caller's start scope) are now one and the same claimed termination. The application's separate claim, finalizer and `stopped` signal are gone.
    - `admit` doesn't compete for the permit once termination has been claimed. Effect's semaphore wakes waiters non-FIFO, so a new request could otherwise overtake it. Instead, such a request waits until termination begins, and is then refused.
- **B2. Buffered events delivered after the bus closed.** Violated D4 and N1.
  - **The defect:** `Stream.fromQueue` takes events in chunks, so events buffered while a subscriber was busy were taken as one chunk and handed over after the close.
  - **Probe P-B2:** four deliveries after resource release.
  - **The fix:** `Event.subscribe` takes one event per pull (`maxChunkSize: 1`). The event being handled finishes; events still queued are discarded with the queue.

**Regression tests** (each fails on `ce37ee2` and passes after the fix):
- `tests/lifecycle.test.ts`: "construction holding admission finishes first; termination waits, then refuses new work from Stopping", for routes 1 and 2 (B1).
- `tests/event.test.ts`: "lets the event being handled finish, but hands over no buffered event after closing" (B2).
- `tests/runtime.test.ts`: "hands no buffered event to a subscriber once resource release has begun" (B2).

**Probes after the fix:**
- P-B2: no deliveries after release.
- P-A: while the admitted construction is still decoding, the status reads `Running` and termination hasn't begun, so work admitted there is within the contract. Once `Stopping` is reached, new work is refused.

**The random race test is replaced** (the audit's B3). The `Math.random()` jitter test in `tests/lifecycle.test.ts` is replaced by four deterministic cases, using gates and scheduler yields, with no sleeps and no randomness:
- **Construction holds admission, route 1 and route 2.** A schema's decode waits on a test-controlled `Deferred`. While it's held:
  - termination is waiting and nothing is released;
  - the status is still `Running`;
  - a `createState` requested meanwhile waits.

  Once the decode gate opens:
  - the construction succeeds;
  - termination enters `Stopping`, held there by a gated release, where `runFork` and a new `createState` are both refused, and so is the waiting request;
  - the created `State`'s `changes` ends with `Success`;
  - the final status is `Stopped`, with exactly one release.
- **Termination has already begun, route 1 and route 2.** Termination is held in `Stopping` by a gated release; `createState` is refused as a defect (`Cause.isDie`, no typed failure); then the status is `Stopped`, with exactly one release.

### Release-gate review, second round: `run`/`runFork` and nested admission

Review of `f57a252` found that B1's fix was incomplete, and inspection found a deadlock.

- **B1, remaining race.**
  - **The defect:** `Runtime.run`/`runFork` didn't take part in admission; `runtimeFor` checked only `accepting`. Take an admitted `createState` holding the admission permit, and a termination that has been claimed and is waiting for it. In that window `accepting` was still true, so `run`/`runFork` started new work. Once the admitted work finished, termination entered `Stopping` and released the runtime while that new work might still be running.
  - **On `ce37ee2`:** the same window reads `Stopping`, and the new work was admitted there as well.
- **Nested admission deadlock.** An admitted effect that requested more admitted work (for example, a schema whose decode calls `createState`) deadlocked in two ways:
  - after termination was claimed, the nested request waited for termination to begin, while termination waited for the outer effect;
  - even without any termination, the admission semaphore had one permit and wasn't reentrant, so the nested request waited forever on the outer one.

**The fix** (`src/runtime/internal.ts`, `src/runtime/index.ts`): the admission semaphore is replaced by a synchronous admission counter plus the termination claim. All the checks and updates are synchronous JavaScript, so each is atomic.
- **The claim ends admission** at once, for every entry point. `admit` (and so `createState`), `run` and `runFork` share one check, `admitting` (not claimed, and still accepting). After the request, all three refuse new work as a defect.
- **`admit` never waits.** Admitted, it increments the count and decrements it when the effect ends, uninterruptibly paired, so the count is right however the effect exits. Refused, it dies at once. A nested request is therefore admitted, or refused, immediately, and can't deadlock.
- **Termination:**
  1. claim;
  2. wait until the admitted count reaches zero;
  3. `onBegin` (`Stopping`), then `accepting = false`;
  4. close the bus;
  5. close the scope;
  6. `onEnd` (`Stopped`).

  Between the request and `Stopping`, the status reads `Running` while new work is refused. That is within "while `Running`, new work *may* be admitted". D1 holds: construction admitted before the request finishes before termination begins.
- **The no-barging guard is gone,** because admission no longer waits for anything. With it goes the liveness caveat recorded in the first round.

**Regression tests,** in `tests/lifecycle.test.ts`, deterministic: gates and scheduler yields only. All of them fail on both `f57a252` and `ce37ee2`:
- **"run and runFork issued while termination waits for admitted work are refused and never execute"** (routes 1 and 2):
  - a gated `createState` holds admission; termination is claimed and waiting; the status is still `Running`;
  - `Runtime.run` rejects as a defect and `Runtime.runFork` exits as a defect, and neither effect ever runs;
  - then the admitted construction completes, the final status is `Stopped`, and there is exactly one release.

  On `f57a252` both calls are admitted and run; on `ce37ee2` the status is already `Stopping` while they're admitted.
- **"an admitted construction that requests another once termination is claimed is refused, not deadlocked"** (routes 1 and 2):
  - the nested `createState`, requested from inside the admitted decode after the claim, is refused;
  - the outer construction completes, and termination reaches `Stopped`.

  It deadlocks on both earlier implementations (it fails by timeout).
- **"lets an admitted construction request another while Running, without deadlock":** both constructions succeed. The non-reentrant semaphore deadlocked this on both earlier implementations.
- **Updated B3 cases 1 and 2:** a `createState` requested after the claim is now refused at once, instead of waiting.

**Probes:** P-A now shows the `runFork` issued while termination waits refused, with its effect never run. P-B2 still shows no deliveries after release.

**Still open, awaiting a decision:** B4, from the fresh audit of `f57a252`. A resource release that dies during termination leaves `onEnd`/`terminated` incomplete, so later `Application.shutdown` calls, and closing the caller's start scope, wait forever. It was reported with options, and isn't changed here.
