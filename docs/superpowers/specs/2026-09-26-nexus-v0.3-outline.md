## Where v0.2 left off

v0.2 (locked 2026-09-26) made a NEXUS application drive MESH v0.5 end to end, in Node:
- `src/mesh`, exported as `Mesh`, is the host adapter between NEXUS core and `@valancex/mesh-runtime`. The MESH compiler is used only at test or build time.
- M1–M4 are normative: exact `Render` provenance, no render retention, explicit bindings only, and a runtime-only dependency.
- `renders` emits future commits only, and fails terminally on a render diagnostic.
- The error taxonomy separates typed failures from defects. A `toInput` throw is a defect.
- Test 9 and the architecture checks enforce the import boundaries.
- `State.changes` completes when its owning scope closes (F-A). This fixed a v0.1 gap the adapter's shutdown test exposed.

v0.2 changed nothing else in the v0.1 core, and its audits covered only MESH-related documentation.

## Audit of v0.2

The audit read ARCHITECTURE, every primitive doc, the v0.1 and v0.2 plans, the v0.2 spec and its errata, every file under `src/` and `tests/`, `examples/`, the package metadata and the git history. It also read MESH's architecture and its "Integrating MESH with NEXUS" guide, and PORT's README, architecture and packages.

### Findings

- **O1. Event subscriptions don't end on shutdown** (P1).
  - `event.md` says the bus is "released with" the application and that its subscriptions complete when the application's scope closes. No test covers this. It's the same class of bug as F-A.
- **O2. The application lifecycle can be bypassed** (P3, P7, P9, and P6 depending on Q1).
  - `RunningApplication.runtime.scope` is a public `CloseableScope`, and `Runtime.shutdown` accepts the application's handle.
  - Both contradict `src/application/index.ts:42-43` ("a public, writable Ref would let any holder forge a lifecycle transition") and the lifecycle in ARCHITECTURE §4.
  - v0.2 made this scope load-bearing (`state.md:58`, and the harnesses in `tests/mesh.test.ts` and `tests/state.test.ts`).
- **O3. The service `Context` is reachable** (P4). This violates `runtime.md:74` and ARCHITECTURE §5 ("must not become a global service locator").
- **O4. Application-owned State has no API.**
  - ARCHITECTURE §4 and §14 say the Runtime owns State. `application.md` lists "initialize state" among the application's responsibilities.
  - The only route today is `Scope.extend(…, running.runtime.scope)`, which is exactly the surface O2 and O3 remove.
- **O5. `publish` doesn't validate** (P2), despite `event.md:66`.
- **O6. The command-name uniqueness rule (`command.md:76`) has nothing to attach to:** there is no application command set.
- **O7. The primitive docs diverge from the code** (D5's table). `primitives/README.md:23` calls any such divergence a bug.
- **O8. Non-Effect callers can't see typed errors** (P5). *Deferred*: documented only (D5).
- **O9. Nobody owns the MESH host composition loop.** *Deferred* (H5).
  - MESH's host has five steps: compile, render, keep, dispatch and map. Its `docs/ARCHITECTURE.md:31` and step 3 of its NEXUS guide say the NEXUS adapter "keeps each render", which contradicts M2.
  - PORT is a scaffold.
- **O10. Capability probing is described but not built.** *Deferred*. Its dead `EnvironmentResolutionFailed` variant is handled under O7.

## Theme

v0.3 is a correctness and coherence release. The ownership and lifecycle model NEXUS already promises (ARCHITECTURE §4, §5, §14 and the primitive docs) becomes true in code, and every primitive's documented contract matches its implementation. There is no new feature family, and the MESH boundary doesn't move.

## Architecture and invariants

### Carried over from v0.2, unchanged

- **M1, render provenance.** `dispatch(render, …)` operates against exactly the supplied `Render` and never substitutes another.
- **M2, no render retention.** The adapter keeps no render registry or cache, and no `Render` for later lookup.
- **M3, explicit bindings only.** An intent with no explicit `commands` entry fails with `UnmappedCommand`.
- **M4, runtime-only dependency.** `src/mesh` uses `@valancex/mesh-runtime` only, never the MESH compiler.
- **Error taxonomy.**
  - Typed failures: `MeshDiagnostics`, `UnmappedCommand`, `CommandValidationError`, and the command's own `E`.
  - Defects: a `toInput` throw, and `TypeError`, `MeshVersionError`, `MeshInternalError` or any other runtime rejection.
- **`renders`.** Future commits only, in commit order. A render diagnostic fails and ends the stream. It ends normally when the owning scope closes.
- **`State.changes`** stays open while its owning scope is alive and completes normally when that scope closes (F-A). Caller-scoped `State.create` keeps exactly this behaviour.
- **Selectors are pure.** `Selector.changes` completes when its underlying `State` does, and `combine` completes when either side does.
- **`Command.invoke`** decodes its input before the handler runs.
- **Import boundaries:** test 9 and the architecture checks. There is no PORT dependency.
- **The MESH v0.5.0 fixture** stays pinned and verbatim.
- **Packaging:** ARCHITECTURE §26, decision 8.

### New in v0.3

- **N1. Shutdown completeness.**
  - Once the application has terminated (N2), every observation stream over application-owned resources has completed with a normal exit, not an interruption and not a failure. That includes:
    - `State.changes` of application-owned `State`;
    - `Selector.changes` derived only from application-owned `State`;
    - `Event.subscribe` streams run against the application's bus (P1);
    - `Mesh.renders` over such a selector.
  - A subscription started after termination completes immediately.
  - Streams over caller-scoped `State` follow their own scope (F-A), not the application's.
- **N2. Lifecycle integrity.**
  - **Two termination routes, and only two:**
    1. `Application.shutdown(running)`;
    2. closing the caller-owned `Scope` in which `Application.start` ran.
  - **No public value can end, or partly end, the application:** no scope, and no runtime-shutdown entry point that accepts the application's handle.
  - **Both routes reach the same end state:** the runtime scope is closed, every resource is released, N1 holds, and the status is `Stopped`.
  - **Status is monotonic** along `Created → Initializing → Running → Stopping → Stopped` (or `Initializing → Failed`), and is never observed moving backwards.
  - **`Application.shutdown` is idempotent and never fails:**
    - on a `Stopped` application it returns immediately and changes nothing;
    - concurrent calls shut down once, and each returns only once the application is `Stopped`;
    - after route 2, it's a no-op.
  - Whether execution is refused after termination is Q1.
- **N3. No ambient Context.**
  - No public NEXUS value exposes the service `Context`, an Effect `Runtime` (which carries one) or the runtime's scope, under any property name.
  - The application's services are reachable only inside effects run through `Runtime.run` or `Runtime.runFork`, through their declared `R`.
- **N4. Contract parity.**
  - **Normative sections:** in each `docs/primitives/*.md`, the Data Model, API, Errors and Rules sections, plus ARCHITECTURE §15 for `Mesh`.
  - Every type, signature, error variant and field they name must match the exported declarations in `dist/**/*.d.ts` exactly.
  - Examples are illustrative, but they may use only APIs that exist.
  - A divergence is a defect. It's resolved only by a recorded decision that either changes the code or corrects the document, never by leaving both.

## Goals

1. Application-owned `State` whose lifetime is the application's (O4).
2. Lifecycle integrity: exactly two termination routes, truthful and monotonic status, and an idempotent shutdown (O2).
3. No raw `Context`, Effect `Runtime` or runtime scope reachable from a public value (O3).
4. Shutdown completion for every application-owned observation stream, including `Event.subscribe` (O1).
5. Every primitive's documented contract reconciled with its implementation (O5, O6, O7).

## Non-goals (v0.3)

- **MESH host composition:** keeping the on-screen render, relaying events, re-rendering (O9, H5).
- **Non-Effect host support** (O8), beyond documenting the current behaviour.
- **PORT;** browser, DOM or renderer work.
- **Capability probing or discovery** (O10).
- **Selector memoization or deduplication;** typed command outputs.
- **Extra event buses,** wildcard subscriptions or replay.
- **Splitting the adapter** into a separate package.
- **Hot reload,** runtime MPRX compilation, composite events.
- **npm publishing.**
- **Any change to M1–M4** or to the `renders` contract.
- **A command registry,** or a capability-resolution architecture.
- **Compatibility wrappers** for removed surface.
- **Fixing MESH's documentation** (see "After v0.3").

## Decisions

### D1. Application-owned State (O4; H1(b))

- **The constructor:** an application-scoped `State` constructor in the `Application` namespace takes the `RunningApplication`, a schema and an initial value. Its name is left to the plan.
- **Ownership:**
  - Any holder of the `RunningApplication` may create one.
  - It requires no `Scope` from the caller; not taking one is what makes the ownership explicit.
  - It is bound to that application, and the application runtime owns its lifetime, which lasts until the application terminates by either N2 route.
- **Errors:** the same `StateInitError` as `State.create`. The behaviour when the application isn't `Running` is Q2. It must never produce a state that outlives the application.
- **Result:** an ordinary `StateHandle<A>`. There is no new kind of state.
- **Access:** commands and other primitives reach it through an explicit handle reference (closures or constructor arguments), as today. It isn't registered in the service graph, and nothing looks it up by name (N3).
- **At shutdown:**
  - its `changes` completes normally (N1) through the F-A mechanism, and derived selectors and `Mesh.renders` follow;
  - `get`/`update`/`set` after termination keep their v0.2 behaviour;
  - a new `changes` subscription completes immediately.
- **`State.create(schema, initial)`** is unchanged, for caller-owned state.

### D2. The `NexusRuntime` surface (O2, O3; H2)

- **The handle:**
  - `NexusRuntime<R>` becomes an **opaque execution handle**, with no readable `scope`, `runtime` or `context` member.
  - `Runtime.run` (Promise) and `Runtime.runFork` (Fiber) accept it, with their v0.2 semantics apart from Q1.
- **Standalone runtimes:**
  - `Runtime.make(layer)` stays public. It's already scoped to the caller's `Scope`, and closing that scope ends a standalone runtime.
  - `Runtime.shutdown` leaves the public API. `Application` uses an internal equivalent.
- **`RunningApplication`** keeps `runtime` (the opaque handle), `status` (through `Application.status`) and `environment`.
  - Its `shutdown` field is removed, leaving `Application.shutdown(running)` as the single sanctioned call.
- **What callers can do:** run effects, read status, request shutdown, and create application-owned `State`.
- **What callers can't do:** close an internal scope, reach the `Context` or an Effect `Runtime`, or change status directly.

### D3. Lifecycle integrity (O2)

N2 is the contract. Route 2, closing the caller's scope, must also move the status to `Stopped` (P7). A repeated or concurrent `Application.shutdown` must not write any status after `Stopped`.

### D4. Shutdown completeness (O1)

N1 is the contract. The application's event bus is released with the application: every subscription completes normally on termination, and a late subscription completes immediately.

## Resolved decisions

- **H1, application-owned State:** (b), an application-scoped constructor bound to `RunningApplication` (D1).
- **H2, the `NexusRuntime` surface:** narrow it to the smallest surface that keeps legitimate execution (D2). This is an intentional public API correction, not a runtime redesign.
- **H3, documented but unbuilt rules:** decided item by item on the repository's evidence (D5):
  - `publish` validation: correct the documentation;
  - command-name uniqueness: correct the documentation, and add no registry;
  - `EnvironmentResolutionFailed`: remove it from the public union.
- **H4, scope:** A + B only. That is lifecycle and ownership closure, plus contract reconciliation.
- **H5, MESH host composition:** deferred. It is recorded under "After v0.3", not designed here.

## Open decisions

- **Q1. Execution after termination** (P6). Once the application is `Stopped`, does an effect run through its handle still execute? Today it does, against services already released.
  - **(a) Refuse:** the effect doesn't run, and the call ends as a defect or an interruption. "`Stopped`" then means what it says, and use-after-release is prevented. It costs one lifecycle check and its tests.
  - **(b) Allow it and document it:** no code change. "`Stopped`" then means "resources released", not "not executing", and use-after-release stays possible.
- **Q2. D1's constructor when the application isn't `Running`** (`Stopping` or `Stopped`).
  - **(a) A defect,** as a forged `Render` is: no new public type. Misuse is treated as a programming error.
  - **(b) A new typed failure:** callers can handle it, but it adds a public error type for what is probably a rare misuse.
  - Either way, the constructor must never produce a state that outlives the application.

This is an intentional breaking change within v0.x. The package is unpublished (0.0.1). There are no compatibility wrappers.

## Definition of Done

Each item is proved by a test written before the change it covers.

- **N1:**
  - an `Event.subscribe` stream forked through the application runtime ends normally after `Application.shutdown`, and after the caller's start scope closes (P1's regression);
  - application-owned `State.changes`, and a `Selector.changes` derived from it, end normally on both routes;
  - a subscription started after termination completes immediately;
  - MESH test 7 still passes, with its harness using D1.
- **N2:**
  - a typecheck-time assertion that `running.runtime.scope`, `running.runtime.runtime` and a public `Runtime.shutdown` don't exist (P3's and P9's regressions);
  - closing the caller's start scope leads to `Stopped` and releases resources (P7's regression);
  - a second `shutdown` leaves `Stopped`, and no `Stopping` is observed afterwards;
  - concurrent `shutdown` calls shut down once, and all return at `Stopped`;
  - status is monotonic on every route;
  - execution after termination follows Q1.
- **N3:**
  - no `context`, `runtime` or `scope` member is reachable at type level;
  - at runtime, the public handle's own enumerable properties lead to no `Context`, Effect `Runtime` or `Scope` (P4's regression).
- **F-A:** the scope-owned `State` test is unchanged; the application-owned test uses D1.
- **MESH tests 1–9:** unchanged, except the `runSlice` line that creates `Team`. Test 9 and the architecture checks are unchanged.
- **Deliberate breaks, repeating v0.2's method.** Each break must make a test fail:
  - drop the Event completion → N1's tests;
  - skip the status update on route 2 → P7's test;
  - let a second `shutdown` rewrite the status → the idempotency test;
  - re-expose the scope or the `Context` → N2's and N3's type tests.
- **N4:** every normative primitive-doc section is checked against `dist/**/*.d.ts`, and every row of D5 is resolved as decided.
- **Clean verification:** a fresh `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm test` and `pnpm build`, on Node 22 and 24.

## Risks

- **The migration touches the v0.2 acceptance harness.** Only `runSlice`'s `Team` creation may change. A diff of `tests/mesh.test.ts` that touches anything else, or any change to `src/mesh`, is out of scope.
- **Making shutdown complete event subscriptions may change event ordering at shutdown.** N1 requires a normal exit, not delivery of anything published during `Stopping`. The plan must say what happens to events published while the application is stopping.
- **Q1 and Q2 affect tests.** The plan can't finish N2's or D1's tests until they're answered.

  - MESH's `docs/ARCHITECTURE.md:31` and step 3 of `docs/guides/integrating-mesh-with-nexus.md` say the NEXUS adapter "keeps each render", which contradicts M2. Correcting that belongs to the MESH repository.
  - PORT's README still describes a "MESH IR → NEXUS runtime → PORT" pipeline.
- **O8, typed errors for non-Effect hosts.** Documented as a limitation in v0.3 (D5). It is revisited only with O9.
- **O10, capability probing and discovery.** Future work, once a platform or renderer needs it.
- **Scope check.** Every v0.3 item maps to an audit finding:
  - D1 → O4;
  - D2 and D3 → O2 and O3;
  - D4 → O1;
  - D5 → O5, O6 and O7.

  No deferred concern (O8, O9, O10's probing, memoization, publishing, PORT) is in scope. O8 appears only as a documentation correction.
